# Risks

**Project:** My Translation App

---

| ID | Risk | Impact | Likelihood | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|
| R-001 | Realtime translation is overbuilt too early, adding complexity and cost before it is needed. | High | Medium | MVP scope explicitly limits to push-to-talk. Continuous listening is out of scope. | Architect | Open |
| R-002 | Translation quality varies by language pair, reducing user trust. | Medium | High | Validate common language pairs. Document known limitations. Display source transcript alongside translation so users can judge accuracy. | Architect / Builder | Open |
| R-003 | Speech-to-text transcription errors reduce trust in audio translation. | Medium | High | Always display the transcript before or alongside the translation. Users can see what was heard and judge the result. | Builder | Open |
| R-004 | API costs escalate with audio usage, particularly for speech processing. | High | Medium | Add duration limits on audio input. Apply rate limiting in a future sprint. Monitor usage. | Architect | Open |
| R-005 | Provider lock-in if abstraction layer is not built correctly. | Medium | Medium | Define provider abstraction interface in backend before first implementation. Document interface in docs/ARCHITECTURE.md. | Architect | Open |
| R-006 | User privacy exposure through audio or text content sent to third-party providers. | High | Medium | Do not permanently store audio or translated text. Do not log user content by default. Document data handling in architecture docs. | Architect / Builder | Open |
| R-007 | Browser microphone permission is denied or unavailable, causing UX failures. | Medium | Medium | Handle permission errors gracefully. Show clear error state explaining what failed and how to resolve it. | Builder | Open |
| R-008 | Supported languages are undefined at start of implementation, creating scope ambiguity. | Medium | High | Record as open question Q-002. Use provider language list as the authoritative source during implementation. | Architect | Open |
| R-009 | Frontend accidentally exposes provider API keys if backend proxy is not enforced. | High | Low | Architecture decision D-007 enforces backend-only key access. Validate in code review during implementation sprint. | Builder | Open |
| R-010 | Text-to-speech scope creep delays MVP delivery. | Low | Medium | TTS is recorded as should-have (D-018). If timeline is at risk, defer TTS to a follow-on sprint. | Architect | Open |
| R-011 | Browser MediaRecorder MIME type output varies across browsers and operating systems. The backend may receive audio in a format it does not support. | Medium | High | Document accepted MIME types and target browsers before Sprint 003. Add explicit MIME type validation to backend. Show a clear error message if the recorded format is not accepted. See planning/QUESTIONS.md Q-011. | Builder | Open |
| R-012 | Azure SDK version dependencies may change between Sprint 002 documentation and Sprint 003 implementation. | Low | Medium | Pin Azure SDK versions at implementation time. Record versions used in the Sprint 003 completion report. | Builder | Open |
| R-013 | Audio blob payloads from the browser may be larger than expected if MediaRecorder uses an uncompressed or high-bitrate format. | Medium | Medium | Define a backend file size limit before Sprint 003 implementation. Validate size on both frontend and backend. Document expected MIME types and compression expectations in Q-011. | Builder | Open |
| R-014 | Provider API quotas and costs may not become visible until load testing or real usage begins. | High | Medium | Add configuration settings for per-request and aggregate limits. Document quota monitoring approach in Sprint 003. Do not hard-code limits in code. | Architect | Open |
| R-015 | DTO definitions may drift from provider response shapes if mapping code is not maintained explicitly. | Medium | Low | Define explicit mapping classes in Infrastructure adapters. Never return raw provider SDK objects to the Application or API layers. | Builder | Open |
| R-016 | Audio duration (60-second limit) cannot be reliably enforced from IFormFile without an audio parsing library. | Medium | Medium | File size (10 MB) enforced in Sprint 003 as the nearest proxy. Exact duration enforcement deferred to Sprint 005+. Documented in validation code (TODO comment) and VALIDATION.md. Q-015 tracks decision on when to resolve. | Builder | Open |
| R-017 | Request body size limits configured via Kestrel and FormOptions do not apply to the in-memory test server used by WebApplicationFactory. | Low | High | Expected and accepted limitation for the test environment. Kestrel limits apply in production. Logical size validation (audioSizeBytes check in TranslationRequestValidator) is tested and functions in all environments. | Builder | Open |
| R-018 | Mock provider output could be misread as real translation if prefixes are removed or overlooked. | Low | Low | All mock outputs are clearly prefixed: "[mock-{lang}]" and "[mock transcript]". Provider name "mock" is returned in all response DTOs. | Builder | Open |
| R-019 | Browser blocks cross-origin requests from frontend (localhost:5173) to backend (localhost:5074) without CORS configuration. | Medium | High | Resolved in Sprint 004: Vite proxy handles /api/* in dev so browser never makes cross-origin requests. Minimal CORS added to Program.cs for localhost:5173 as belt-and-suspenders. Neither is a production CORS policy — production CORS must be designed when hosting is decided. | Builder | Mitigated (dev) |
| R-020 | Frontend parses wrong error field if `errorCode` vs `code` naming drift between docs and backend DTOs is not caught. | Medium | Low | Resolved in Sprint 004: frontend types use `errorCode` to match actual `ApiErrorResponseDto` JSON serialisation. D-038 documents the discrepancy from the Architect Pack. | Builder | Resolved |
| R-021 | Azure credentials accidentally committed to source control. | High | Medium | User Secrets used for local dev. Placeholders only in appsettings.json. Secrets checked before sprint completion. D-042. | Builder | Mitigated |
| R-022 | Azure SDK packages leak into Application layer, breaking the architecture constraint. | Medium | Low | Verified: Application.csproj has zero Azure package references. Only Infrastructure.csproj holds Azure SDKs. D-039. | Builder | Mitigated |
| R-023 | WebM audio format from browser is not supported by Azure Speech SDK compressed path (requires GStreamer on Windows). | Medium | Was High | Sprint 005.2 resolved: compressed audio (MP3, WebM, OGG) now uses the Azure Speech Fast Transcription REST API, which handles codec decoding server-side. No GStreamer required. D-049. | Builder | Mitigated |
| R-024 | MP4 audio format is not supported by Azure Speech SDK container formats. | Low | Medium | `AzureSpeechToTextProvider` throws `ProviderException(UNSUPPORTED_AUDIO_FORMAT)` for `audio/mp4`. Documented in README. | Builder | Mitigated |
| R-025 | Azure Speech STT auto-detect language is not implemented. Defaults to en-US if source language is null or "auto". | Low | Medium | Documented in README and blueprint. Sprint 006 or later to address if auto-detect is required. Q-008 tracks final policy. | Builder | Open |
| R-026 | Placeholder credential values in appsettings.json pass startup validation but fail on first Azure call. | Low | Low | Expected behaviour — documented in D-045 and tests. Startup only checks for non-empty values. Invalid credentials fail at the provider call, not startup. | Builder | Accepted |
| R-027 | Browser `MediaRecorder` MIME type support differs between Chrome, Edge, Firefox, and mobile browsers. The selected MIME type affects which Azure pipeline path is used. | Medium | High | `AudioCaptureService` detects the best supported type at runtime via `MediaRecorder.isTypeSupported()` (D-056). Phase 0 confirmed Chrome 148 selects `audio/webm;codecs=opus`. Firefox uses `audio/ogg`. Graceful fallback if no supported type found. | Builder | Mitigated |
| R-028 | Users may deny browser microphone permission, preventing recording. | Medium | Medium | Permission denial must be caught and surfaced as a clear, user-friendly error. UI must reset to Idle state. Sprint 006 acceptance criterion AC-006. | Builder | Open |
| R-029 | Mobile browser (Safari/iOS) `MediaRecorder` support is limited and may differ from desktop. | Low | Medium | Safari/iOS is out of MVP scope. Sprint 006 targets Chrome and Edge (primary) and Firefox (secondary). If no supported MIME is detected, `AudioCaptureService` returns an unsupported-browser error rather than failing silently. | Builder | Open |
| R-030 | Chrome `MediaRecorder` blob Content-Type (`audio/webm`) might not be accepted by the Azure Fast Transcription API. | High | Was High | MITIGATED — Phase 0 live test (2026-05-30) confirmed HTTP 200, full transcript and translation returned. Chrome 148 → `audio/webm` → Azure Fast Transcription → success. Q-025 resolved. | Builder | Mitigated |
| R-031 | Azure voice names may not be available on all Azure Speech resource SKUs or regions. | Medium | Medium | Voice map uses standard Azure Neural voices (JennyNeural, ElviraNeural, etc.) which are broadly available. Fallback uses SpeechSynthesisLanguage if voice is not mapped. Live validation required to confirm. | Builder | Open |
| R-032 | TTS can increase Azure usage costs. | Low | Medium | Playback is user-initiated only (D-059). Not auto-generated on every translation. | Architect | Open |
| R-033 | Browser audio autoplay may be blocked. | Low | Medium | Mitigated by design — playback is triggered by explicit user click on the Play button. | Builder | Mitigated |
| R-034 | Audio object URLs leak memory if not revoked. | Low | Medium | Mitigated — `ResultPanel` revokes the object URL in `audio.onended` and before creating a new URL on a subsequent Play click (`stopCurrentAudio`). | Builder | Mitigated |
| R-035 | Visual changes may accidentally break functionality. | Medium | Medium | Preserve all CSS class names used conditionally in component logic. Only visual properties change. TypeScript check and build clean confirm no regressions. | Builder | Open |
| R-036 | Mobile layout regressions after responsive CSS additions. | Medium | Medium | Explicit validation at 320px, 375px, 768px, 1024px, and 1440px required before Sprint 008 is marked complete. | Builder | Open |
| R-037 | Over-engineering the UI in Sprint 008 — adding unnecessary complexity or new dependencies. | Medium | Low | No new npm packages. No CSS framework. No state management changes. Scope is visual polish and documentation only. | Builder | Open |
| R-038 | Azure Translator and Azure Speech language support may differ. | Medium | High | Builder verified supported languages for translation, STT, and TTS before finalizing the catalog. All 37 languages have confirmed support across all three services. | Builder | Mitigated |
| R-039 | TTS voice mapping can become fragile as the catalog grows. | Medium | Medium | Explicit voice map maintained for all 37 languages. Fallback uses `SpeechSynthesisLanguage` if a voice name is unavailable. Live validation required per R-031. | Builder | Open |

| R-042 | Azure voice availability differs by resource region or SKU — voices in the map may not be available on all deployments. | Medium | Medium | Play button disables gracefully via `supportsTextToSpeech: false` when set. Live validation required per R-031 and R-039. | Builder | Open |
| R-043 | API response change (`GET /api/languages` adding 3 fields) could break frontend consumers that use exact-shape type guards. | Low | Low | Only additive fields added. `code` and `name` preserved. TypeScript interface updated in lockstep. No other known consumers. | Builder | Mitigated |
| R-044 | `targetLangSupportsTts` lookup in `App.tsx` could fail if language code in the result does not match any catalog entry. | Low | Low | `?? true` fallback ensures Play button defaults to enabled if the language is not found — safe and preserves existing behavior. | Builder | Mitigated |
