# Decisions

Record durable project decisions here.

**Project:** My Translation App

---

| ID | Date | Decision | Rationale | Owner |
|---|---|---|---|---|
| D-001 | 2026-05-28 | MVP is a browser-based web app. | Widest reach with no install required. Mobile browser covers the travel and in-person use case. | Architect |
| D-002 | 2026-05-28 | MVP supports typed text translation. | Core use case. Lowest friction entry point for users. | Architect |
| D-003 | 2026-05-28 | MVP supports push-to-talk audio translation. | Enables spoken language use case without continuous listening complexity. | Architect |
| D-004 | 2026-05-28 | Continuous real-time translation is out of scope for MVP. | Real-time architecture adds significant complexity and cost. Push-to-talk covers the immediate need. | Architect |
| D-005 | 2026-05-28 | MVP does not require user accounts or authentication. | Reduces friction and implementation complexity. No personalisation or history persistence in MVP. | Architect |
| D-006 | 2026-05-28 | Translation history is session-only in MVP. | Avoids the need for a database, user identity, and privacy/compliance complexity in MVP. | Architect |
| D-007 | 2026-05-28 | Backend proxies all external provider API calls. Frontend never holds provider secrets. | Security posture. Exposing API keys in a browser app is a critical vulnerability. | Architect |
| D-008 | 2026-05-28 | Audio and translated text are not permanently stored in MVP. | Privacy and simplicity. Reduces compliance risk and storage requirements. | Architect |
| D-009 | 2026-05-28 | Full user audio and translated text are not logged by default. | Privacy protection. Logging user speech or translation content creates data retention and compliance risk. | Architect |
| D-010 | 2026-05-28 | Azure Speech and Azure Translator are the recommended first provider direction. | Single vendor reduces integration surface area. Azure provides both STT/TTS and translation in one platform. Final choice TBD. | Architect |
| D-011 | 2026-05-28 | A provider abstraction layer is required in the backend. | Allows swapping Azure for OpenAI, DeepL, Google, or others without frontend changes. Prevents provider lock-in. | Architect |
| D-012 | 2026-05-28 | PostgreSQL is deferred until user persistence is needed. | Not required for session-only MVP. Introduce only if accounts, history, or settings become in scope. | Architect |
| D-013 | 2026-05-28 | React is the recommended frontend framework. | Broad ecosystem, good mobile browser support, suitable for interactive translation UI. | Architect |
| D-014 | 2026-05-28 | .NET is the recommended backend framework. | Used as API proxy and service layer. Strong typing and good Azure SDK support. | Architect |
| D-015 | 2026-05-28 | Mobile-friendly layout is the design priority. | Translation tools are frequently used while travelling or speaking in person on mobile devices. | Architect |
| D-016 | 2026-05-28 | Backend normalises provider API responses before returning to frontend. | Decouples frontend from provider-specific response shapes. Supports provider swapping without frontend changes. | Architect |
| D-017 | 2026-05-28 | Errors returned to frontend must be structured and safe. | Prevents exposure of provider error messages, internal stack traces, or sensitive context to the browser. | Architect |
| D-018 | 2026-05-28 | Text-to-speech playback is a should-have feature for MVP, not a blocker. | Adds value but the core workflow (text and push-to-talk translation) is usable without it. Final scope TBD. | Architect |
| D-019 | 2026-05-28 | React frontend uses a structured folder layout: app, components (translation, audio, layout, feedback), hooks, services, types, utils, validation. | Provides consistent code organisation and clear separation between UI, logic, and API access from the start. | Architect |
| D-020 | 2026-05-28 | .NET backend uses a layered folder layout: Api (Controllers, Middleware, Contracts), Application (Translation, Speech, TextToSpeech, Validation, Interfaces), Infrastructure (Providers/Azure, Configuration, Logging), Domain (Models, Errors), Shared. | Enforces SOLID principles, separates concerns, and keeps provider-specific code isolated in Infrastructure. | Architect |
| D-021 | 2026-05-28 | Provider abstraction interfaces (ISpeechToTextProvider, ITextTranslationProvider, ITextToSpeechProvider, ILanguageCatalogService) belong to the backend Application layer, not Infrastructure. | Interfaces belong with the application logic that depends on them. Infrastructure adapters implement them. This prevents Infrastructure from defining the contract. | Architect |
| D-022 | 2026-05-28 | No URL-based API versioning for MVP. DTOs are named explicitly and structured to support future additive versioning without breaking changes. | API versioning adds friction in MVP. Explicit DTO naming and careful field design avoids breaking changes when the API evolves. If a breaking change becomes necessary, introduce a new endpoint path at that time. | Architect |
| D-023 | 2026-05-28 | Frontend state is divided into three tiers: local UI state in components, translation session state in React Context, and external API calls via a lightweight service layer. Redux and Zustand are deferred unless state complexity requires them. | Keeps MVP state simple and testable. Context covers shared session state. Service layer decouples API calls from components. | Architect |
| D-024 | 2026-05-28 | Backend logging must not include raw audio, source text, or translated text. Correlation IDs and timing metrics are permitted in logs. | Prevents user content from appearing in logs, which creates privacy, compliance, and data retention risk. Correlation IDs and timing are safe operational data. | Architect |
| D-025 | 2026-05-28 | Audio is delivered to the backend as a short blob upload via multipart/form-data. No streaming or WebSocket audio path in MVP. | Consistent with push-to-talk design (D-004). Simple upload is easier to validate, rate-limit, and audit. | Architect |
| D-026 | 2026-05-28 | PostgreSQL integration, if ever introduced, plugs into the Infrastructure layer only. No Application or Domain layer changes are required to add persistence. | Persistence is deferred (D-012). When introduced, it must not force rewrites of application services or domain models. | Architect |
| D-027 | 2026-05-28 | Backend skeleton uses mock providers only in Sprint 003. | Allows endpoint and validation work without secrets or Azure coupling. Real provider integration begins in Sprint 005. | Builder |
| D-028 | 2026-05-28 | Text translation MVP character limit is 5,000 characters. | Keeps validation simple and avoids excessive provider cost exposure. Resolves Q-009. | Builder |
| D-029 | 2026-05-28 | Audio recording MVP duration limit is 60 seconds. | Aligns with push-to-talk MVP and reduces upload/processing risk. Resolves Q-010. | Builder |
| D-030 | 2026-05-28 | Accepted MVP audio MIME types are: audio/webm, audio/webm;codecs=opus, audio/mp4, audio/mpeg, audio/wav. MIME matching normalises by stripping parameters before comparison. | Covers common browser outputs. Normalisation prevents audio/webm;codecs=opus from being rejected when audio/webm is in the allowed list. Resolves Q-011. | Builder |
| D-031 | 2026-05-28 | All API responses (success and error) include a correlationId field. Middleware reuses the X-Correlation-ID request header if present; otherwise generates a new GUID. | Supports frontend/backend tracing without logging sensitive content. Reuse of incoming correlation ID enables end-to-end trace continuity. | Builder |
| D-032 | 2026-05-28 | Backend source structure separates Api, Application, Infrastructure, and Tests into distinct .NET projects within one solution. | Enforces dependency direction at compile time. Application has zero Infrastructure references. | Builder |
| D-033 | 2026-05-28 | TTS endpoint is not implemented in Sprint 003. ITextToSpeechProvider interface is defined as a future placeholder only. | Keeps Sprint 003 focused on text/audio translation skeleton. | Builder |
| D-034 | 2026-05-28 | Backend targets .NET 8 LTS (SDK 8.0.303). | .NET 8 is the current LTS release and aligns with the ASP.NET Core shared framework available in the development environment. | Builder |
| D-035 | 2026-05-28 | Frontend uses React 18 + TypeScript + Vite 5. | No prior frontend convention existed. React aligns with D-013. TypeScript provides type safety against backend DTOs. Vite provides fast local dev. | Builder |
| D-036 | 2026-05-28 | Vite dev server proxies /api/* to the backend (http://localhost:5074). Minimal CORS added to Program.cs for localhost:5173 as belt-and-suspenders. Neither is a production CORS policy. | Proxy approach avoids browser CORS blocking in dev without exposing a broad CORS policy. The backend CORS registration is scoped to the Vite origin only. | Builder |
| D-037 | 2026-05-28 | Audio input in Sprint 004 is a standard file upload (`<input type="file">`). Browser microphone recording (MediaRecorder / push-to-talk) is deferred to Sprint 006. | Keeps Sprint 004 focused on end-to-end contract validation. File upload is simpler, testable with any audio file, and does not require microphone permission handling. | Builder |
| D-038 | 2026-05-28 | Frontend error parsing uses `errorCode` (not `code`) to match the actual `ApiErrorResponseDto.ErrorCode` JSON serialisation. Error details contain `field` and `message` only — no `code` field at the detail level. | Matches the actual backend DTO structure. The Architect Pack section 15 used `code` which was a documentation discrepancy — the backend serialises to `errorCode`. | Builder |
| D-039 | 2026-05-28 | Azure provider adapters are confined to the Infrastructure layer only. Application layer has zero Azure SDK references. | Enforces the provider abstraction architecture. Swapping providers requires only Infrastructure changes. | Builder |
| D-040 | 2026-05-28 | Provider selection is configuration-driven via `Translation:Provider`. Supported values: `Mock`, `Azure` (case-insensitive). | Allows switching providers without code changes. User Secrets or environment variables supply real credentials in Azure mode. | Builder |
| D-041 | 2026-05-28 | Mock provider remains the safe default. The default `Translation:Provider` value is `Mock`. | Ensures the app starts and tests pass without any Azure credentials present. Azure mode is explicitly opted into. | Builder |
| D-042 | 2026-05-28 | Azure credentials are supplied via .NET User Secrets or environment variables. Never committed to source control. `appsettings.json` contains placeholder strings only. | Prevents accidental credential exposure in version control. User Secrets are stored outside the repo. | Builder |
| D-043 | 2026-05-28 | `ProviderException` is defined in the Application layer with an `ErrorCode` property. `ExceptionHandlingMiddleware` catches it and returns HTTP 502 with the specific error code. | Application defines the contract (exception type + codes). Infrastructure throws it. Api handles it. Keeps error code semantics (PROVIDER_ERROR, TRANSLATION_FAILED, etc.) surfaced to the frontend. | Builder |
| D-044 | 2026-05-28 | `ProviderName` is a property on `ITextTranslationProvider` and `ISpeechToTextProvider`. Each implementation returns its own name string ("mock" / "azure"). `TranslationService` reads it to populate the `provider` field in response DTOs. | Keeps the provider name dynamic and accurate without coupling `TranslationService` to configuration or specific provider types. | Builder |
| D-045 | 2026-05-28 | Azure Speech SDK startup validation only checks for non-empty `Key` and `Region`. Placeholder strings ("DO_NOT_COMMIT_REAL_KEY") pass startup and fail only on the first real API call. | Startup validation guards against missing config. Detecting invalid-but-present credentials at startup would require a test Azure call, which is undesirable. | Builder |
| D-046 | 2026-05-28 | WAV audio is handled via temp file + `AudioConfig.FromWavFileInput` in the Azure Speech provider. Compressed audio (MP3, WebM) uses `AudioInputStream.CreatePushStream` with the appropriate container format. Temp files are always deleted in a finally block. | WAV format detection requires reading the WAV header, which `FromWavFileInput` does automatically. Compressed formats use the push stream with explicit container format. No temp files for non-WAV audio. | Builder |
| D-047 | 2026-05-30 | `Azure.AI.Translation.Text` is pinned to **1.0.0** (Translator API v3.0), not the latest 2.0.0 (API 2026-06-06). | SDK 2.0.0 targets API version `2026-06-06`, which is not supported by standard Azure AI Services multi-service resources (Cognitive Services endpoint). These resources only expose Translator at the v3.0 path. The 1.0.0 SDK targets v3.0 and is compatible with all standard Azure resources. The `TranslateAsync(string, string, string, CancellationToken)` convenience overload exists in both versions — no provider code change was required. Sprint 005.1 remediation. | Builder |
| D-048 | 2026-05-30 | Backend integration tests (`TranslationControllerTests`, `ProviderSelectionTests`) explicitly pin `Translation:Provider=Mock` via `WithWebHostBuilder`. | `WebApplicationFactory` loads User Secrets in the Development environment. If User Secrets override `Provider=Azure`, tests that rely on mock output break. Pinning Mock in test factories makes tests environment-independent. | Builder |
| D-049 | 2026-05-30 | Compressed audio (MP3, WebM/Opus, OGG/Opus) is transcribed via Azure Speech **Fast Transcription REST API** (`/speechtotext/transcriptions:transcribe?api-version=2025-10-15`) instead of the Speech SDK compressed push-stream path. WAV remains on the SDK path unchanged. | The SDK compressed-audio path requires GStreamer on Windows — unavailable on standard dev machines. The short-audio REST endpoint (`/speech/recognition/conversation/cognitiveservices/v1`) only supports WAV and OGG/Opus, not MP3 or WebM. The Fast Transcription API supports all required formats without native codec dependencies. Sprint 005.2 remediation. | Builder |
| D-050 | 2026-05-30 | `AzureSpeech:Endpoint` added as a required config field alongside `Key` and `Region`. The endpoint is the base URL of the Azure AI Services resource (e.g. `https://my-resource.cognitiveservices.azure.com`). `IsConfigured` now requires all three. | The Fast Transcription API endpoint is resource-name based, not region based. `Region` is still required for the WAV SDK path (`SpeechConfig.FromSubscription`). Startup validation catches missing `Endpoint` in Azure mode before the first request. | Builder |
| D-051 | 2026-05-30 | `audio/ogg` added to `AllowedAudioMimeTypes` in `TranslationValidationOptions`. | `MapToContainerFormat` (Sprint 005) had a code path for OGG but it was silently rejected at the validation layer before reaching the provider. Firefox MediaRecorder outputs `audio/ogg`. Sprint 005.2 makes validation consistent with the Fast Transcription API's OGG support. | Builder |
| D-052 | 2026-05-30 | `MediaRecorder` is the primary browser audio capture mechanism for push-to-talk. | Standard browser API. No third-party library required. Supported in all target browsers (Chrome, Edge, Firefox). | Architect |
| D-053 | 2026-05-30 | Push-to-talk (press to start, press to stop) is the MVP interaction model for browser audio capture. | Aligns with the MVP domain model. Lower complexity than hold-to-record. No streaming required. | Architect |
| D-054 | 2026-05-30 | Audio is uploaded as a blob after recording completes. No streaming transcription in MVP. | Consistent with D-025 (blob upload). Keeps the existing `/api/translate/audio` endpoint unchanged. | Architect |
| D-055 | 2026-05-30 | Chrome and Edge are the primary validated browsers for Sprint 006. Firefox is supported where `MediaRecorder` formats are compatible (`audio/ogg`). | Phase 0 confirmed Chrome 148 produces `audio/webm;codecs=opus` and the full pipeline succeeds. Firefox uses `audio/ogg`, already accepted by the backend since Sprint 005.2. Safari/iOS not in MVP scope (R-029). | Architect |
| D-056 | 2026-05-30 | `AudioCaptureService` detects supported MIME types at runtime using `MediaRecorder.isTypeSupported()` and selects the first supported format from the preference list: `audio/webm;codecs=opus`, `audio/webm`, `audio/ogg;codecs=opus`, `audio/ogg`. | Phase 0 confirmed Chrome 148 selects `audio/webm;codecs=opus`. Preference order ensures best format is chosen per browser without hardcoding. Graceful failure if no supported type found. | Architect |
| D-057 | 2026-05-30 | `AudioTranslationForm` retains file upload as a fallback tab alongside the new push-to-talk Record tab. Push-to-talk is the default active tab. | File upload remains useful for testing (upload a known audio file to isolate backend issues from recording issues) and for users with pre-recorded files. Tab approach adds negligible scope. | Architect / Builder |
| D-058 | 2026-05-30 | Text-to-speech playback is included in Sprint 007 as part of the MVP communication loop. | Users may need to communicate verbally with someone who does not read the target language. Text-only output is useful but incomplete for real-world in-person communication. Azure Speech is already configured and supports TTS without a new resource. | Architect |
| D-059 | 2026-05-30 | TTS is requested on demand via a Play button. Speech is not generated automatically after every translation. | Avoids unnecessary Azure usage and cost. Keeps initial translation response fast. Gives users control over when audio is generated. | Architect |
| D-060 | 2026-05-30 | TTS endpoint is `POST /api/translate/tts`. Returns binary audio (MP3 in Azure mode) with `Content-Type: audio/mpeg`. Correlation ID is returned in `X-Correlation-ID` response header. | Dedicated endpoint keeps translation endpoints focused. Binary response body cannot carry a JSON correlationId field — the response header is the established convention for the `X-Correlation-ID`. | Builder |
| D-061 | 2026-05-30 | `AzureTextToSpeechProvider` uses a voice map for 10 supported languages and falls back to `SpeechConfig.SpeechSynthesisLanguage` (Azure default voice) for unmapped codes. | Prevents ProviderException for languages not in the voice map. Azure selects a reasonable default voice for any locale it supports. Errors for truly unsupported languages surface naturally from the SDK. | Builder |
| D-062 | 2026-05-30 | `MockTextToSpeechProvider` returns a 44-byte minimal silent PCM WAV (`audio/wav`) instead of empty bytes. | Allows integration tests to verify a non-empty binary response and exercise the full frontend playback flow (object URL creation) without Azure credentials. Azure mode returns `audio/mpeg`; mock returns `audio/wav`. | Builder |
| D-063 | 2026-05-30 | Sprint 008 focuses on product presentation. No major feature development is permitted. Focus areas: UX, visual polish, mobile responsiveness, accessibility, portfolio readiness. | Sprint goal is to transform the technically complete MVP into a portfolio-quality product visible to recruiters and technical reviewers. | Architect |
| D-064 | 2026-05-30 | All primary user workflows must be reviewed on mobile screen sizes (320px, 375px, 768px, 1024px, 1440px). | Translation tools are used on mobile devices during travel and in-person communication (D-015). Mobile responsiveness is a first-class requirement, not an afterthought. | Architect |
| D-065 | 2026-05-30 | A dedicated `design/` folder is introduced as part of the project. Contains `inspiration/`, `screenshots/`, `decisions.md`, and `style-guide.md`. | Formalises design assets as project artifacts. Supports portfolio documentation requirements. | Architect |
| D-066 | 2026-05-30 | Portfolio assets (`portfolio/`) are first-class deliverables of Sprint 008. Includes case study, architecture overview, demo script, and lessons learned. | A recruiter or technical reviewer must be able to understand the project from documentation alone without running the app. | Architect |
| D-067 | 2026-05-30 | Sprint 008 CSS strategy: introduce CSS custom properties at `:root` for the full color and radius system. Plain CSS only — no external CSS framework or utility library introduced. | Custom properties allow future dark-mode or theme changes without a full CSS rewrite. No new npm packages keeps the dependency surface minimal. | Builder |
| D-068 | 2026-05-30 | Sprint 008 adopts a dark navy theme across the full page (body background `#0d1117`, surface cards `#161b2e`). Header gradient uses `#0d1117` → `#1a1a2e` → `#1e1b4b`. Accent color for CTAs: indigo `#6366f1`. | Consistent with the design inspiration direction (images 1, 7, 8). Separates structural chrome (dark) from CTA actions (accent) for clear visual hierarchy. | Builder |
| D-069 | 2026-05-30 | Application name "My Translation App" is retained in Sprint 008. Q-033 (branding) remains open. | Branding decision is deferred to the project owner. No placeholder name is hardcoded by the Builder. | Builder |
| D-070 | 2026-05-31 | Language expansion is handled as Sprint 009A, independently of deployment prep. | Language support affects validation, UI, translation, speech, and TTS mapping — testing independently before deployment reduces risk. | Architect |
| D-071 | 2026-05-31 | The app distinguishes between translation support, STT support, and TTS support per language. These are not assumed to be identical. | Azure Translator may support more languages than Azure Speech STT/TTS. All three maps are maintained separately in the codebase. | Architect |
| D-072 | 2026-05-31 | German (`de`) covers Austria for MVP. Austrian dialect/voice localization is not a separate language entry. | "Austrian" is not a distinct Azure Translator language code. Austria is served by German. Austrian German voice selection can be addressed in a future sprint if needed. | Architect |
| D-073 | 2026-05-31 | Mandarin Chinese is represented as "Chinese (Simplified)" (`zh`) and "Chinese (Traditional)" (`zh-Hant`) in the catalog. | D-068 direction: Mandarin should be explicitly represented. Traditional Chinese is included as Q-035 recommends including it when Azure support is straightforward. | Architect |
